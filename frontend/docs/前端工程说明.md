# 轻步 LightStep · 微信小程序前端（Vue + uni-app）

> 学习不用急，一步就好。
>
> 本仓库是「轻步 LightStep」的**微信小程序前端**，从后端 `lightstep-backend` 的 16 个接口反向搭建。
> 所有文案、语气、状态机都由后端 `persona.py` / `services.py` 决定，前端只负责「把当前这一步摆到屏幕正中间」。

## 0. 三个核心界面

| 对话建任务（首页） | 单步执行 | 今日回执 |
| --- | --- | --- |
| ![对话建任务](docs/screenshots/chat.png) | ![单步执行](docs/screenshots/focus.png) | ![今日回执](docs/screenshots/receipt.png) |

（这三张是在 H5 端以 390×844 逻辑像素、接真实 mock 后端跑出来的实际渲染，不是设计稿。）

## 1. 它和后端是什么关系

```
┌────────────────────────────┐        ┌─────────────────────────────┐
│ pages/chat      对话建任务  │        │                             │
│ pages/focus     单步执行    │  HTTP  │  FastAPI  lightstep-backend  │
│ pages/receipt   今日回执    │ ─────► │  /api/*  16 个接口           │
│ pages/journal   静默手帐    │  JSON  │  SQLite  三层记忆 + 摩擦地图 │
│ pages/history   历史        │ ◄───── │  LLM(mock/openai) 拆解+情绪  │
│ pages/settings  设置        │        │                             │
└────────────────────────────┘        └─────────────────────────────┘
        user_id = 本地生成的身份（后端没有账号系统）
```

- **前端不产生业务状态**：任务的拆解、粒度、下一步是什么，全部由后端算。
- **前端只做三件后端做不了的事**：本地输入与交互、温和召回的计时、回执图片的生成。
- **没有接口的功能一律标注「待接入」**，不 mock 后端能力（见第 9 节）。

## 3. 启动方式

### 3.1 先起后端（必需）

```bash
cd lightstep-backend
pip install -r requirements.txt
python run.py            # http://127.0.0.1:8000
```

默认 `LLM_PROVIDER=mock`，**不需要任何 API key** 就能跑通全流程（预设拆解 + 规则情绪识别）。
要用真 LLM：复制 `.env.example` 为 `.env`，改 `LLM_PROVIDER=openai` 并填 `LLM_API_KEY`（DeepSeek / 豆包 / OpenAI 都行）。

### 3.2 前端：HBuilderX（推荐，零安装）

1. HBuilderX → `文件 → 导入 → 从本地目录导入`，选 `D:\lightstep\lightstep-frontend`（**不是** `lightstep-backend`）。
2. 右键 `manifest.json → 微信小程序配置`，填入你的小程序 AppID；没有就先去[微信公众平台](https://mp.weixin.qq.com)申请一个测试号/个人号，或直接在开发者工具里用「测试号」。
3. `运行 → 运行到小程序模拟器 → 微信开发者工具`。
4. 微信开发者工具里必须做这一件事，否则所有请求都会失败：
   `详情 → 本地设置 → 勾选「不校验合法域名、web-view（业务域名）、TLS 版本以及 HTTPS 证书」`
5. 底部「网络」面板能看到 `http://127.0.0.1:8000/api/session/open` 返回 `200` 就通了。

> 项目是**非 CLI 工程**（没有 `package.json` / `node_modules`），HBuilderX 自带编译器直接就能跑，
> 不需要 `npm install`。这一点是刻意的：黑客松现场换台电脑也能立刻跑起来。

### 3.3 前端：真机预览

真机上 `127.0.0.1` 指的是手机自己，必须换成电脑的局域网 IP：

1. 后端改成对外监听：`uvicorn app.main:app --host 0.0.0.0 --port 8000`
2. 小程序里改地址，有两种方式：
   - 改代码：`config/index.js` 的 `DEFAULT_BASE_URL = 'http://192.168.1.8:8000'`
   - 不改代码：`设置 → 后端地址 → 改`（写入本地缓存，优先于默认值）
3. 手机和电脑同一个 Wi-Fi；微信开发者工具「预览」扫码。

### 3.4 前端：CLI 构建（可选，用于 CI / 提交审查）

非 CLI 工程本身不需要构建，但如果要打 CI 或做静态检查，可以临时包一层：

```bash
npm i -D @dcloudio/vite-plugin-uni@vue3 @dcloudio/uni-app@vue3 vite@5.2.8
npx uni build -p mp-weixin      # 产物在 dist/build/mp-weixin
```

（本项目开发时就是这样验证的：用 uni-app vue3 编译器 5.36（`@dcloudio/*@3.0.0-alpha-50306…`）+ vite 5.2.8
在隔离目录里跑过 `uni build` 与 `uni build -p mp-weixin`，两个平台都是 `Build complete`，无告警级错误。
业务层另有 22 条端到端断言（打真实后端）与回执 canvas 绘制检查，全部通过 —— 见第 11 节。）

## 5. 页面结构与路由

`pages.json` 里只有 6 个页面。一级入口有三个（手账 / 对话 / 设置），由**自绘的底部选择栏** `components/TabBar.vue` 切换。

> 为什么不用 `pages.json` 的原生 `tabBar`：①它要求 81×81 图标资源，而这套视觉是纯文字极简风格；②原生选中态只有「文字颜色」一个维度，做不出胶囊高亮；③原生 tab 页只能用 `switchTab` 且不能带参数。自绘后用 `uni.reLaunch` 切换，页面栈恒为 1 层。

| # | 路由 | 导航栏 | 对应策划书 | 职责 |
| --- | --- | --- | --- | --- |
| 1 | `pages/chat/chat` | custom | F1 对话式建任务、9.1 五件小事 | 首页（默认 tab）。初始态=居中小猫+「我们要开始做什么呢？」；说一句话 → 后端拆解 → 选开始时间 |
| 2 | `pages/focus/focus` | custom | F2 单步展示、F3 召回、F4 无惩罚退出 | 全屏只有当前这一步（不在一级入口里） |
| 3 | `pages/receipt/receipt` | custom | F6 完成回执、9.2 | 票根式回执，生成 / 存相册 / 攒手帐（不在一级入口里） |
| 4 | `pages/journal/journal` | 系统默认 | 9.2 私人静默手帐 | 按时间排的回执列表（底部 tab 1） |
| 5 | `pages/history/history` | 系统默认 | 9.3 历史（藏得深） | 只记做了什么（设置页最底部进入） |
| 6 | `pages/settings/settings` | 系统默认 | F5 感官友好、9.3 历史入口 | 开关 + 联调项（底部 tab 3） |

**跳转关系**

```
        ┌──────────── 底部 TabBar（手账｜对话｜设置，reLaunch 切换）────────────┐
        │                                                                      │
   chat ─┴─(state 变 executing)──► focus ──(完成/收尾，离开 executing)──► chat
     │
     └──(点「今天到此为止」)──► receipt ──(关掉)──► 返回

   settings ──(最底下一行小灰字「看看之前做了什么」)──► history
```

跳转由 `store/session.js` 的 `navIntent` 驱动：后端一返回 `state === 'executing'`，对话页就 `navigateTo` 单步页；
离开执行态（`done` / `idle`）单步页自己退回对话页。页面之间不互相 import，只通过 store 通信。

## 6. 状态管理方案

### 6.1 为什么是「极简 reactive store」而不是 Pinia

HBuilderX 3.4+ 的 vue3 编译器虽然内置了 Pinia，但**非 CLI 工程**能否解析到它取决于 HBuilderX 版本和模板，
是「拿到代码打不开」最常见的原因之一。所以这里用 Vue3 自带的 `reactive` 写了 20 行等价物
（`store/defineStore.js`），零依赖：

```js
export const useFoo = defineStore('foo', {
  state: () => ({ n: 0 }),
  actions: (state) => ({ inc() { state.n += 1 } })
})
const foo = useFoo()      // 单例，写法与 Pinia 完全一致
```

迁移回 Pinia 只需替换 `defineStore.js` 的实现，业务代码一行都不用改（见附录 A）。

### 6.2 store 划分

| store | 存什么 | 是否持久化 |
| --- | --- | --- |
| `user` | `user_id`（本地生成的身份，`u_xxx`） | ✅ `lightstep_user` |
| `settings` | `sensory` 感官友好 / `dnd` 勿扰 / `showAllSteps` | ✅ `lightstep_settings` |
| `session` | 消息列表、`state`、`task`、计时、`navIntent` | ❌ 只存内存（后端才是真相） |

### 6.3 单向数据流

```
用户操作（点按钮 / 发一句话）
        │
        ▼
session.dispatchLabel(label) 或 session.sendChat(text)
        │   按钮文案 → 具体接口（LABEL_ACTIONS 映射表）
        ▼
api/index.js → api/request.js → 后端
        │
        ▼
applyReply(reply)   ← 唯一的状态写入口
  ├─ state       ← reply.state
  ├─ task        ← reply.task（TaskView，字段名与后端一致）
  ├─ reminders   ← reply.due_reminders
  ├─ messages.push(气泡)
  ├─ 计时：只在 executing 且 current_step 变化时重置 stepStartedAt
  └─ navIntent   ← 进/出执行态
        │
        ▼
页面只渲染 store（ChatBubble 等组件不含业务）
```

**按钮不写死**：后端在 `buttons` 里给的是中文标签（`现在开始` / `行` / `完成这一步`…），
`session.js` 里的 `LABEL_ACTIONS` 把标签映射到接口；遇到不认识的标签，兜底当成一句话发给 `/api/chat`。
所以后端将来改按钮文案，前端不会崩，最差的情况是那句话被当成普通对话。

## 7. 请求与鉴权处理

### 7.1 鉴权现状（重要）

**后端没有登录、没有 token、没有账号系统**（策划书第 11 节明确不做用户账号）。
所以：

- 身份 = 客户端本地生成的 `user_id`（`u_` + 随机串 + 时间戳），持久化在 `uni` 本地缓存；
- 每个请求都显式带上 `user_id`：写操作放 JSON body，读操作放 query；
- 换设备 / 清缓存 = 换一个人，摩擦地图和手帐都会重新开始（这是设计，不是 bug）。

`api/request.js` 里仍然预留了鉴权位：

```js
function buildAuthHeaders() {
  const token = uni.getStorageSync('lightstep_token')
  if (token) headers.Authorization = 'Bearer ' + token   // 后端加 JWT 时自动生效
  return headers
}
```

后端将来加 `POST /api/auth/login` 时，只要把 token 写进 `lightstep_token`，全站请求自动带上，接口层不用改。

### 7.2 错误处理

`api/request.js` 把三类失败统一成 `ApiError { status, detail, url, kind }`：

| 情况 | `kind` | 提示 |
| --- | --- | --- |
| 请求失败 / 后端没起 | `network` | 没连上小步。确认后端已在 8000 端口启动，并勾选「不校验合法域名」。 |
| 超时 | `timeout` | 小步想太久了。再试一次，或者先把任务说短一点。 |
| 4xx / 5xx | `http` | 按状态码查中文文案（422 会把 FastAPI 的 `detail[]` 拼成「user_id：Field required」这种可读提示） |

文案都在 `api/errors.js` 的 `STATUS_TEXT` 里，改提示只改这一处。
请求层默认 `uni.showToast`，页面里需要自己处理时可以传 `{ silent: true }`。

### 7.3 现场排错顺序

1. 浏览器打开 `http://127.0.0.1:8000/docs` → 有 Swagger 就说明后端活着；
2. 开发者工具「网络」面板看请求是否发出、状态码是多少；
3. `ECONNREFUSED` → 后端没起 / 端口不对；
4. `request:fail url not in domain list` → 忘了勾「不校验合法域名」；
5. 真机全是超时 → 用了 `127.0.0.1`，换成局域网 IP（第 3.3 节）。

## 8. 关键页面交互逻辑

### 8.1 对话建任务（`pages/chat/chat.vue`）

- 冷启动调 `POST /api/session/open`，后端可能回三种开场：继续昨天的任务 / 跨天交接（`接着做`·`翻篇`）/ 日常问候。
- 输入一句话 → `POST /api/chat`，后端用关键词做意图识别（建任务 / 收尾 / 换事 / 记笔记 / 发呆 / 情绪兜底），
  前端**不做任何意图判断**。
- 气泡里的按钮直接用后端返回的 `buttons`：`现在开始` `待会儿` `今天不做`。
- 「5 件小事」快捷条：`换件小事` / `发呆` / `今天什么都不想干` / `走神记笔记` / `温柔收尾`，
  前四个等价于把那句话发过去（走后端同一套意图识别），`走神记笔记` 会切到笔记模式（`POST /api/note`）。
- 「今天到此为止」直接进回执页（纯前端，不打后端）。
- 小步的姿势跟着今日步数变（`GET /api/daily/summary` 的 `steps_done`）：0 步瘫着、1–2 步半睁眼、
  3–4 步坐起来、5 步以上伸懒腰。

### 8.2 选开始时间 + 5 分钟轻承诺

| 按钮 | 接口 | 结果 |
| --- | --- | --- |
| 现在开始 | `POST /api/task/choose_time { when: 'now' }` | `state: committing`，出 `行` / `再想想` |
| 待会儿 | `{ when: 'later' }` | 后端登记 **30 分钟后**的提醒，`due_reminders` 会带出来 |
| 今天不做 | `{ when: 'not_today' }` | 清空当前任务，回到 `idle` |
| 行 | `POST /api/task/commit { agree: true }` | `state: executing` → 前端跳单步页 |
| 再想想 | `{ agree: false }` | 退回 `ready` |

> ⚠️ 策划书写的是「现在 / 5 分钟后 / 10 分钟后」，后端只实现了 `now` / `later(=30 分钟)` / `not_today`。
> 前端**照后端的真实能力**渲染，没有伪造 5 / 10 分钟。要改成策划书那样，需要后端把 `later` 拆成
> `in_5min` / `in_10min`（见第 9 节）。

### 8.3 单步执行（`pages/focus/focus.vue`）

- 整屏只有 `task.current_step`，一个字都不多。没有进度条、没有倒计时、没有下一步预览。
- 底部两个按钮 + 一句很小的「还是有点重」：
  - **这步做完了** → `POST /api/step/complete { duration_ms }`
  - **今天到这吧** → `POST /api/task/exit`（不弹确认、不留记录）
  - **还是有点重** → `POST /api/step/resize { direction: 'smaller' }`
- `duration_ms` 是**真实耗时**：从这一步出现在屏幕上开始计时，点「做完了」时算差值
  （最小 1s、最大 30min 兜底）。后端用它判断：< 15s 加量、> 90s 拆细、中间保持 —— 这就是自适应粒度的唯一输入。
- 换了一步会重播一次 0.5s 的淡入上移（感官友好模式下自动关掉）。
- 任务完成或收尾后，单步页自己退回对话页。

### 8.4 温和漂移召回（`composables/useSoftRecall.js`）

- 前台运行才计时：`onHide` 停表、`onShow` 重新起表（切后台不算走神）。
- 任何 `touchstart` 都重置计时（滚动也算碰屏幕）。
- 5 分钟完全没碰 → 屏幕下方轻轻浮一句 `我在这儿，需要了叫我`，8 秒后自己沉下去。
- 最多 2 次，之后安静等待，绝不催第三次。
- 角落的「勿扰」开关一开，整套召回完全不触发。

### 8.5 隐形番茄钟（`composables/useFiveMinuteAnchor.js`）

- 进入执行态起一个 5 分钟定时器，**界面上没有任何数字在跑**。
- 到点后底部出现两个很小的按钮：`就到这吧` / `再来 5 分钟`。
- 不挽留、不追问；点「到这」等同收尾。

### 8.6 无惩罚退出

点「今天到这吧」→ `POST /api/task/exit` → 后端返回一句温柔收尾 + 今日小结 →
前端把**除这一句以外的所有气泡全部清掉**。没有「确定要放弃吗」，没有「为什么走」，没有「半途而废」标记。

### 8.7 今日回执（`pages/receipt/receipt.vue`）

- 屏幕上那张票根是 CSS 画的（`ReceiptCard.vue`）；「存到相册」时用 canvas **重画一份同版式的图**
  （小程序没法直接截 DOM），逻辑在 `utils/receipt.js`。
- 版式：2:3 竖版、奶白纸面、左右半圆齿孔、极小页眉「轻步 · 今日回执」→ 小步 → 大字「今天到此为止」
  → 虚线 → 「写给自己的一句话」+ 三行空白 → 右下角日期。
- 手写那句话**只画在图上，不上传**；只有用户主动点「攒进手帐」才会 `POST /api/journal/add`。
- 授权被拒会引导去 `openSetting`，不会静默失败。

### 8.8 私人静默手帐 / 历史

- 手帐：`GET /api/journal` 列表 + 输入一句 `POST /api/journal/add` + `DELETE /api/journal/{id}`。
  后端在「任务全部完成」和「温柔收尾」时会自动写一条回执，所以列表里本来就有东西，前端不重复写。
- 历史：`GET /api/history`，只有「日期 + 做了什么」，没有耗时、没有完成率、没有图表。
  入口在**设置页最底下一行很小的灰字**，首页永远不会出现。

### 8.9 感官友好模式

`App.vue` 里所有颜色都是 CSS 变量；给根节点加上 `.theme-sensory` 就整体换成纯黑白，
同时 `--dur: 0s` 关掉所有过渡，`animation: none` 关掉淡入。

## 10. 前后端联调注意事项

1. **先跑 `smoke_test.py`**：`python smoke_test.py` 会跑一遍主流程 + 摩擦地图 + 跨天交接 + 手帐，
   后端自身不出问题再联调前端，能省一半时间。
2. **`user_id` 别乱改**：摩擦地图（`friction` 表）、跨天交接（`handoff` 表）、手帐都挂在 `user_id` 上。
   想演示「摩擦地图生效」，用同一个 `user_id` 连续三次点「太重了」，第四次建同类任务时粒度会变细。
3. **演示跨天交接**：把 SQLite 里 `users.last_seen` 改成昨天再重新打开小程序（`smoke_test.py` 里就是这么做的），
   不用等到第二天。
4. **`duration_ms` 一定要传真实值**：写死一个常量，自适应粒度和摩擦地图都不会动，
   路演讲「它发现我状态不错就把下一步加量了」就演不出来。
5. **真机调试换 IP**：`127.0.0.1` 在手机上指向手机自己。
6. **别把 `lightstep.db` 提交到仓库**：演示数据（手帐条目）会跟着一起走。
7. **改后端口径**：所有用户可见的话都在 `app/persona.py`，前端不要自己拼「加油」「太棒了」这类词，
   否则会破坏人设一致性（`FORBIDDEN` 列表里明确禁止）。

## 附录 A：迁移到 Pinia

```bash
npm i pinia
```

```js
// store/defineStore.js 换成：
import { defineStore as piniaDefine, createPinia } from 'pinia'
export const pinia = createPinia()
export function defineStore(id, options) {
  return piniaDefine(id, { state: options.state, actions: options.actions })
}
```

`main.js` 里 `app.use(pinia)` 即可。业务代码（`useSession()` / `session.sendChat()`）完全不变。

## 附录 B：字段命名约定

- **后端字段一律原样保留**：`current_step`、`steps_done`、`due_reminders`、`granularity`、`notes_to_recall`
  （不做 camelCase 转换，避免出现「同一个东西两种叫法」）。
