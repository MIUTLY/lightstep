# 后端 v2 增量说明（任务森林 / step_id / 生成澄清）

> 对应仓库 `MIUTLY/lightstep` main `ce27b686`「Merge PR #12: 真实AI任务森林生成及失败保留」。
> 本文件只记录**相对上一版（7f75a7d）的增量**，完整字段映射见 [字段映射与联调说明.md](字段映射与联调说明.md)。

## 1. 新增 4 个接口（任务生成）

| 方法 | 路径 | 请求 | 说明 |
| --- | --- | --- | --- |
| POST | `/api/task/generate` | `{ user_id, goal }` | 直接按目标生成任务（内部与 `/api/chat` 走同一个 `_create_task`） |
| GET | `/api/task/generation` | `?user_id=` | 查当前生成草稿：`{ generation: {...} \| null }` |
| POST | `/api/task/generation/retry` | `{ user_id, generation_id }` | 生成失败后重试 |
| POST | `/api/task/generation/answer` | `{ user_id, generation_id, answer }` | 回答澄清问题后重新生成（一般用 `/api/chat` 发「补充：…」即可） |

前端落地：`api/index.js` 里 `generateTask / generationStatus / retryGeneration / answerGeneration`。

## 2. `Reply` 新增 `generation`

```json
{
  "reply": "…",
  "state": "idle",
  "buttons": [],
  "task": null,
  "generation": {
    "generation_id": "4eec685e1fa64fbf8e244723da57e52e",
    "original_input": "我要准备期末考试",
    "goal": "我要准备期末考试",
    "answers": [{ "question": "…", "answer": "…" }],
    "status": "needs_clarification | succeeded | failed | draft",
    "question": "你需要准备哪些具体科目…",
    "error": null,
    "updated_at": "2026-11-07T19:45:08"
  }
}
```

前端把它存进 `session.generation`，用于三件事：

| status | 前端行为 |
| --- | --- |
| `needs_clarification` | **`buttons` 是空数组**，只能靠用户打字。对话页把输入框切成「补充：」模式（placeholder 显示模型在问什么），发送时若用户没写前缀会**自动补上** `补充：` |
| `failed` | `buttons` 里会出现 **`重试生成`**（在原有按钮之前），点击 → `POST /api/task/generation/retry`；原始输入已保留，已有任务和进度不受影响 |
| `succeeded` | 正常出任务，`task.plan_format = "forest_v1"` |

> ⚠️ 澄清**可能连续追问多轮**（实测有过两轮）。前端不用特殊处理：只要 `status` 还是 `needs_clarification`，输入框就一直是补充模式。

## 3. `TaskView` 新增 4 个字段

```json
{ "title": "…", "current_step": "…", "steps_done": 0, "granularity": "normal",
  "state": "ready", "step_id": "cb64…:r0.0:cad0…", "start_due_at": null,
  "plan_format": "forest_v1", "node_id": "r0.0", "parent_id": null,
  "remaining_leaf_ids": ["…", "…", "…"] }
```

| 字段 | 前端用途 |
| --- | --- |
| `plan_format` | `legacy`（旧的线性三档）或 `forest_v1`（任务森林节点树）。前端只用于判断长文本，暂无分支逻辑 |
| `node_id` / `parent_id` | 森林节点身份，前端暂不展示 |
| `remaining_leaf_ids` | 剩余叶子节点**id 列表**（没有文字），所以仍然**不能**做「显示全部步骤」 |
| `step_id` | **必须回传**：`/api/step/complete` 与 `/api/step/resize` 的 `step_id` 参数，后端用它确认「完成的确实是当前这一步」 |

### 实测：森林模式的 `current_step` 会很长

```
梳理考试范围与现有复习材料（本次内容：确认大学英语期末考试词汇与阅读的具体题型和分值；
整理教材、词汇表和阅读练习中需复习的单元范围；列出当前词汇和阅读的薄弱点清单）
```

89 个字。所以 `pages/focus/focus.vue` 加了**字号自适应**：

| `current_step` 长度 | 字号 |
| --- | --- |
| ≤ 40 字 | 56rpx（原样） |
| 41–80 字 | 44rpx（`step-md`） |
| > 80 字 | 34rpx（`step-sm`） |

## 4. 请求体也变严了

`/api/step/complete` 与 `/api/step/resize` 可选带 `step_id`；其余请求校验同上一版
（`user_id`/`message`/`content` 非空、`duration_ms` 非负整数、`agree`/`gentle` 严格布尔、
`when`/`direction` 为 Literal 枚举）。类型不对直接 422。
