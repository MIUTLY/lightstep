## 2. 通用数据结构

### 2.1 `Reply`（1–10 号接口都返回它）

后端定义：`app/schemas.py::Reply`

```json
{
  "reply": "好，那我们先把标题写出来。 什么时候开始？",
  "state": "ready",
  "buttons": ["现在开始", "待会儿", "今天不做"],
  "task": {
    "title": "写课程论文",
    "current_step": "打开文档，把标题写出来",
    "steps_done": 0,
    "granularity": "normal",
    "state": "ready"
  },
  "notes_to_recall": [],
  "due_reminders": [],
  "summary": null
}
```

| 字段 | 类型 | 含义 | 前端用在哪 |
| --- | --- | --- | --- |
| `reply` | string | 小步这一句台词，可能为空串 | 气泡正文 |
| `state` | string | 会话状态机，见第 4 节 | `session.state`，驱动跳转 |
| `buttons` | string[] | 后端建议的按钮**中文标签** | `ActionBar` 渲染 + `LABEL_ACTIONS` 映射动作 |
| `task` | TaskView \| null | 当前任务快照 | `TaskCard`、单步页大字 |
| `notes_to_recall` | string[] | 想起来的便签 | 目前后端从不填（便签是拼进 `reply` 里的），前端只做兼容读取 |
| `due_reminders` | string[] | 到点的提醒文案 | 气泡下方的「提醒：…」 |
| `summary` | string \| null | 今日小结（收尾 / 完成 / 退出时才有） | 气泡里虚线分隔的一段绿字 |

> ⚠️ `notes_to_recall` 在实测中永远是 `[]`：`services.py` 的 `note_recall()` 是把便签拼进 `reply` 文本里返回的。
> 前端两份都支持，但不要以为有单独的便签列表接口。

### 2.2 `TaskView`

```json
{ "title": "写课程论文", "current_step": "打开文档，把标题写出来",
  "steps_done": 0, "granularity": "normal", "state": "ready",
  "step_id": "60cad5a9661f4c3fa520fb7d38795234:s0", "start_due_at": null }
```

| 字段 | 枚举 / 范围 | 含义 | 前端展示 |
| --- | --- | --- | --- |
| `title` | string | 任务标题（后端从用户那句话里剥掉语气词得到） | 任务卡标题 |
| `current_step` | string | **当前这一步**（只能看到这一步） | 单步页 56rpx 居中大字 |
| `steps_done` | int | 已完成小步数 | 任务卡小字「已完成 N 小步」；决定小步姿势 |
| `granularity` | `fine` / `normal` / `coarse` | 粒度档位（摩擦地图调档后的结果） | 任务卡小字「粒度 细/中/粗」 |
| `state` | 见第 4 节 | 任务自身状态 | 任务卡右上角胶囊 |
| `step_id` | string，可能为 `""` | 当前动作的**稳定标识**（形如 `3f2a…:s0`） | 不展示；用于判断「换了一步」以重置计时 |
| `start_due_at` | string \| null | 预约开始的 UTC ISO 时间；消费/取消后为 `null` | 不展示倒计时；有值时显示「约好了，到点轻轻提醒你」+「现在就开始了」 |

> **`step_id` 为什么重要**：粒度切换后可能出现两步文字完全相同、但它们是不同动作
> （后端 PR 里叫「保留动作顺序与步骤计时身份」）。只按 `title|current_step` 比较会漏掉/误触计时重置，
> 所以 `session.js::syncStepTimer()` **优先用 `step_id`**，没有时才退回文字比较。
>
> **仍然没有**「完整步骤数组」「总步数」「进度」。`levels_json` 存在库里但 `_task_view()` 从不外发，
> 所以策划书的「显示全部步骤」必须在后端加接口后才能做，不能在 `TaskView` 上猜。

### 2.3 `JournalEntry` —— ⚠️ 已废弃，改为本地结构

后端 `/api/journal` 现在返回 410，`JournalEntry` 不再由后端提供。
前端本地结构（`utils/localJournal.js`）如下，字段刻意沿用后端旧命名，方便迁移：

```json
[{ "id": "l_mw61sukja2bm", "date": "2026-11-07", "steps_done": 2,
   "titles": ["写课程论文"], "note": "今天有点累",
   "created_at": "2026-11-07T15:02:11", "imagePath": "wxfile://saved/xxx.png" }]
```

| 字段 | 说明 | 前端展示 |
| --- | --- | --- |
| `id` | 本地生成（`l_` + 时间戳 + 随机），删除用 | 删除按钮 |
| `date` | `YYYY-MM-DD` | `formatDateCN()` → `11月7日` |
| `steps_done` | 写入时从 `/api/daily/summary` 取的值 | 小字「N 小步」 |
| `titles` | 同上，来自 `daily/summary.titles` | 条目主标题（`、` 连接） |
| `note` | 用户补写的那句话，可能为空串 | 条目下方正文 |
| `created_at` | `YYYY-MM-DDTHH:mm:ss` | 目前不展示（避免变成时间统计） |
| `user_id` | 后端直接返回库行，多带了这个字段 | 前端忽略 |

> 注意：`titles_json` 是数据库列名，接口里已经变成 `titles`（数组）；前端不要去找 `titles_json`。

### 2.4 `HistoryItem`（`GET /api/history`）

```json
[{ "date": "2026-11-07", "title": "写课程论文" }]
```

只有这两个字段，按 `date DESC` 最多 30 条。**没有**耗时、完成率、连续天数。

### 2.5 `DailySummary`（`GET /api/daily/summary`）

```json
{ "date": "2026-11-07", "steps_done": 1, "titles": ["写课程论文"] }
```

前端只用 `steps_done` 决定小步姿势：

| steps_done | 姿势 | 代码 |
| --- | --- | --- |
| 0 | 完全瘫着、眯眼 | `catPoseOfSteps()` → `sleep` |
| 1–2 | 眼睛半睁 | `awake` |
| 3–4 | 坐起来一点 | `sit` |
| ≥5 | 伸懒腰 | `stretch` |

### 2.6 其他两个写接口的返回

```json
// POST /api/journal/add
{ "id": 2, "reply": "记下了。想看的时候去翻翻。" }

// DELETE /api/journal/2?user_id=u_xxx
{ "deleted": true, "reply": "好，删掉了。" }
```

这两个**不是** `Reply` 结构（没有 `state` / `buttons`），前端只取 `id` / `deleted` 并 toast，不进 `applyReply()`。

## 4. 状态机（前端唯一需要认的枚举）

```
                    ┌─────────────────────────────┐
                    │            idle             │ ◄── 打开 / 收尾 / 今天不做
                    └──────────┬──────────────────┘
                    说一句话   │
                    ┌──────────▼──────────────────┐
                    │           ready             │ 按钮：现在开始 / 待会儿 / 今天不做
                    └──────────┬──────────────────┘
                 choose_time=now│            later → 登记 30min 提醒，仍留在 ready
                    ┌──────────▼──────────────────┐
                    │         committing          │ 按钮：行 / 再想想（再想想 → ready）
                    └──────────┬──────────────────┘
                     commit=行 │
                    ┌──────────▼──────────────────┐
                    │         executing           │ 按钮：完成这一步 / 太重了 / 今天到这吧
                    └──────────┬──────────────────┘      ▲ 前端同时跳 focus 页
              step/complete    │                       │ step/resize
                    ┌──────────▼──────────────────┐    │
                    │ done（全部小步做完）        │────┘
                    └─────────────────────────────┘
```

- 前端只在 `executing ↔ 其他` 的边界做跳转（`session.navIntent`）。
- `ready` / `committing` 都留在对话页，用气泡里的按钮推进。
- `done` 之后没有「继续」，要么回 `idle`，要么重新建任务。

## 5. 按钮标签 → 动作映射（`store/session.js::LABEL_ACTIONS`）

| 后端 `buttons` 标签 | 前端动作 | 实际请求 |
| --- | --- | --- |
| 现在开始 | choose_time | `POST /api/task/choose_time { when: "now" }` |
| 待会儿 | choose_time | `POST /api/task/choose_time { when: "later" }` |
| 今天不做 | choose_time | `POST /api/task/choose_time { when: "not_today" }` |
| 行 | commit | `POST /api/task/commit { agree: true }` |
| 再想想 | commit | `POST /api/task/commit { agree: false }` |
| 完成这一步 | step_complete | `POST /api/step/complete { duration_ms }` |
| 太重了 | resize | `POST /api/step/resize { direction: "smaller" }` |
| 太简单了 | resize | `POST /api/step/resize { direction: "bigger" }` |
| 今天到这吧 | exit | `POST /api/task/exit { gentle: true }` |
| 接着做 | handoff_resume | `POST /api/handoff/resume` |

## 6. 错误码

后端是 FastAPI + Pydantic，**没有自定义业务码**，只有 HTTP 状态码。

| 状态码 | 后端来源 | 实测 body | 前端提示 |
| --- | --- | --- | --- |
| 200 | 正常 | `Reply` | — |
| 404 | 路径不存在 | `{"detail":"Not Found"}` | 找不到这条记录，可能已经被删掉了。 |
| 405 | 方法用错 | `{"detail":"Method Not Allowed"}` | 接口方式不对（前端调用错了方法）。 |
| 422 | Pydantic 校验失败 | `{"detail":[{"type":"missing","loc":["body","user_id"],"msg":"Field required","input":{...}}]}` | 参数格式不对：`user_id：Field required` |
| 500 | 未捕获异常 | `{"detail":"Internal Server Error"}` | 小步这边出了点状况，等一下再试。 |
| 0（无响应） | 后端没起 / 域名被拦 / 超时 | `request:fail ...` | 没连上小步。确认后端已在 8000 端口启动，并勾选「不校验合法域名」。 |

422 的 `detail` 是数组，`api/errors.js::formatValidationDetail` 会把 `loc` 里去掉 `body` 后拼成
`字段名：原因`，多个用「；」连接，避免把 JSON 直接甩给用户。
