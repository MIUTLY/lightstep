# 前后端分离技术方案与开发分工

确认日期：2026-11-07。依据：用户提供的最新版策划文本，以及随后确认采用 FastAPI + SQLite 的决定。本文件替代原策划第12节技术方案、第14节技术分工及“所有数据只存本地”的表述。

## 技术结构

| 层 | 技术 | 负责内容 |
| --- | --- | --- |
| 小程序 | uni-app / Vue | 页面、动效、感官模式、前后台生命周期、勿扰、回执绘制和本地手帐 |
| HTTP 服务 | FastAPI | 对话入口、模型调用、任务拆解、完成与调整步骤、当前任务状态、模型结构/语义检查与明确失败 |
| 服务端存储 | SQLite | 当前任务、步骤进度、偏好和摩擦地图；便签沿用已有服务端实现；预约已停用 |
| 外部服务 | 兼容接口的大模型供应商 | 基于目标和必要任务上下文生成步骤与回复，密钥仅由后端持有 |

不建设账号体系，不增加 MySQL 或独立数据库服务器。服务端需要一个可运行 Python 的部署环境；SQLite 文件放在该环境的持久目录，不能假定容器重启后临时文件仍在。当前客户端传入 user_id 是演示身份，不能视为正式身份认证。正式开放使用前需要补充身份归属方案。

## 调用与状态归属

1. 小程序普通对话先由真实AI区分闲聊、提出任务和澄清回答。闲聊返回自然回复；任务先提取清单并在对话页明确范围，再选择和生成森林。只有focus非空才进入专注，详见[对话与澄清协议](chat-and-clarification.md)。失败保存可重试输入并保留旧任务。
2. 小程序发送开始、完成、调整、退出等动作，服务端更新状态后返回结果。
3. 页面以响应中的 state 和 task 渲染，不在客户端另算一份步骤进度。
4. 回到前台后读取 /api/session/state 或 /api/session/open 恢复状态；服务器请求失败时保留当前展示并允许重试，不虚构完成。
5. 任务计时、预约和无操作召回全部取消；网络超时保留。未完成跨天保留、整项完成从待办移除，回执/手帐事实单独保存，见[生命周期](task-lifecycle.md)。
6. 回执生成和保存不调用业务后端，不上传回执图片或“写给自己”的留言。

## 数据归属

| 数据 | 权威位置 | 约束 |
| --- | --- | --- |
| 当前任务、步骤进度、任务状态 | FastAPI + SQLite | 客户端仅缓存展示，重新打开以接口响应为准 |
| 粒度偏好、摩擦地图 | SQLite | 前端反馈动作，后端更新；不在两端独立学习 |
| 走神便签 | 当前服务端实现 | 便签保持当前任务状态；旧提醒表仅保留历史兼容数据，不再投递 |
| 勿扰、感官模式、展示开关 | 客户端本地 | 不需要服务端接口 |
| 回执图片、“写给自己”的留言、本地手帐索引 | 客户端本地 | 只有用户主动保存才持久化；不自动攒、不上传、不统计 |
| 未完成任务与回执/手帐事实 | SQLite；图片及留言仅客户端 | 未完成跨天保留，完成项移出待办；回执/手帐长期保留 |

小程序中需要把生成图片移入本地持久文件，再保存日期与文件位置索引；临时画布路径不能作为长期手帐。删除手帐项时同步处理文件与索引，处理空间不足和写入失败，失败不能提示已保存。清除小程序数据或换设备无法保证恢复；自行保存到相册的图片由用户管理。具体接口选用须由前端成员按实际工程验证。

## 五人分工

| 角色 | 负责内容 | 本轮后续交付 |
| --- | --- | --- |
| 队长 | 产品取舍、视觉资产、路演 | 确认未决的退出等规则，确认演示流程 |
| 前端A | 目标输入、聊天、开始确认、单步执行 | 调用后端接口，以返回任务为准，不在前端重复拆任务 |
| 前端B | 动效、感官模式、勿扰、本地回执和手帐 | 生命周期与本地文件处理，明确存储失败与恢复行为 |
| 后端A | 大模型接入、提示词、步骤生成、情绪与语义理解 | 输出校验、超时提示、普通提问不覆盖任务 |
| 后端B | 接口、SQLite、任务状态、偏好、粒度规则、测试 | 修复状态和参数错误，保证调整不跳过必要动作 |

模块目录是分工约定，不代表权限隔离。接口变化共同沟通，按任务开分支、提 PR，由另一位队员检查后合并。

## 比赛范围与待定项

优先完成文字建任务、真实AI调用与可重试失败、单步执行、即时拆小、退出、感官模式和主动回执。语音、自由重排、完整历史与应用内图片手帐的优先级由队长确认，不以占位目录代表完成。

未定规则：退出是否二次挽留、旧版日志保留期限、猫姿态数量。原策划第5节流程为空，需补齐。此次确认架构并不自动决定这些产品规则。

## 本轮实现与边界

- 现有后端原本已提供 HTTP 接口与 SQLite；本轮补齐分离部署配置、服务健康检查和明确的数据归属。
- 取消任务完成或退出后的自动服务器手帐；旧手帐接口返回 410 JOURNAL_CLIENT_ONLY，不读取或保存回执留言。
- 新数据库不创建 journal 表；旧数据库原有 journal 表与数据不自动删除，也不自动传给客户端。旧数据迁移须单独决定。
- 修复记便签后响应 idle、但数据库仍 executing 的状态错误。
- 网页调试页的手帐留言只在浏览器本地保存，只有主动点击“记下”才写入；它不是小程序图片回执的完整实现。
- 仓库已有小程序源码，由前端成员维护；本轮后端验证不代表已完成 uni-app 联调、图片手帐或相册保存。
