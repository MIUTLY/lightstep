# LightStep 已确认需求与待定规则

更新日期：2026-11-07。

## 来源与决定

- 最新产品来源：用户提供的《粘贴的文本 (1).txt》，在此前 PDF 基础上补充了摩擦地图、本地手帐及跨天规则。
- 用户随后确认采用前后端分离：uni-app 小程序 + FastAPI + SQLite；回执及留言保存在客户端本地。
- 以 [architecture.md](architecture.md) 的技术和数据分工替代原策划“无后端、所有数据本地存储”的描述。
- 原始业务基线为 lightstep-backend(1).zip；现有网页调试页位于 backend/static/，不是微信小程序成品。

## 产品主线

聊天或输入目标 → 选择目标 → 现在/5分钟/10分钟后开始 → 五分钟轻承诺 → 单步执行及主动拆小 → 自主结束与可选回执。默认只显示当前一步，不催促、不吓人、不追究退出。

前台无操作五分钟召回、最多两次、支持勿扰，与轻承诺的五分钟独立计时；没有触摸不等于用户走神。

## 已确认技术边界

- 任务、步骤进度、偏好和摩擦地图在后端 SQLite 管理，客户端不能另行推进一份进度。
- 模型供应商密钥只放后端；实际运行只使用真实AI，不提供mock/离线任务或固定模板兜底。测试替身仅隔离测试使用。
- 任务步骤须可执行，调整不得跳过必要动作。主动反馈优先，耗时仅作辅助信号。
- 普通步骤提问不得创建或覆盖目标；便签操作前后任务状态一致。
- 回执图片与私人留言不上传、不分析、不自动保存；只有用户主动选择后存到本地或相册。
- 新实现停用服务端手帐写入与查询；旧 journal 数据不自动删除。
- 客户端负责计时、动效、勿扰和感官模式，实际小程序实现待前端源码接入。

## 真实AI生成与失败规则（2026-11-07最新确认）

- 生成必须围绕原始具体目标，领域仅作偏好分类，不能替代目标。结构和内容均需检查，关键歧义可简短追问。
- 未配置、连接失败、超时、结构/内容不合格必须明确说明，不返回准备好、不建半成品。
- 草稿保存原始输入、目标、澄清问答和错误，可重开后重试。旧任务及叶子完成集合在AI成功并通过检查前保留；并发进度变化时拒绝覆盖并提示重试。
- 成功后保存整片森林；查看/完成/轻重切换使用存储关系，不请求AI。AI不可用不妨碍这些操作；新建/替换必须等AI成功。
- 旧任务沿用兼容路径，不在本轮迁移或删除。跨天既有规则仍是独立待定事项，本轮生成失败本身不触发跨天清理。
- 本轮只改后端和文档；前端、轻承诺计时、回执和手帐由对应任务验收。

## 三层任务森林（用户于2026-11-07确认）

- 新任务一次生成轻/中/重三层完整对应关系，根为重、中间为中、叶子为轻；数量随内容变化，不强制1重2中4轻。
- 新任务默认第一个未完成的中任务。主动轻重选择逐档切换：加重取对应父节点，减轻取当前节点下第一个未完成的子节点；最轻/最重保持原档位。
- 内部进度只用已完成叶子集合。切换不完成内容；完成当前节点才消费本次要求的剩余叶子；父节点完成情况由叶子集合推导。已完成部分不重做。
- 当前父任务完整时明示本次叶子动作；部分完成时只显示“这一段还剩：…”及未完成叶子，不沿用会暗示重做的完整父文案。
- 完成后按当前档位进入下一段未完成内容，跨树继续；耗时反馈仍记录，但新森林不因此自动改档，保证主动选择优先。旧任务沿用旧队列规则，不强行推测转换。
- 关系、节点、当前选择及叶子完成集合持久化到现有SQLite任务JSON。重开/进程重启恢复一致；跨天沿用现有交接政策，不重新决定数据保留。
- 执行态按钮提供“轻一点/完成这一步/重一点”，并保留原结束入口；选时和承诺阶段保持既有流程。前端由其他成员负责，本轮只改后端和接口文档。
- 结束只表示本次生成范围完成，不夸大为长期目标全部完成。模型语义质量仍需真实任务样本核验。

结构、接口、旧数据及验收细节见[任务森林协议](task-forest.md)。
