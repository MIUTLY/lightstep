# LightStep 后端需求边界

更新日期：2026-11-07（北京时间）

## 来源与当前基线
- 产品来源：用户提供的《轻步 LightStep · 黑客松项目策划 (3).pdf》。
- 代码基线：用户提供的 lightstep-backend(1).zip。本次同步保留原始业务源码，不包含修复。
- 目标：帮助启动困难的学习者将目标化为眼前可执行的一小步；不催促、不吓人、不记账。
- 前端目标是 uni-app 微信小程序；现有 static/ 是网页调试界面。

## 产品主线
聊天/输入目标 → 选择任务 → 现在/5分钟/10分钟后开始 → 5分钟轻承诺 → 单步执行和即时拆小 → 自主结束及可选回执。
默认只显示一步；设置可显示全部步骤并调整顺序。任何时候允许退出。
轻承诺到期后提供结束或续5分钟；前台无操作5分钟召回、最多2次、支持勿扰，是另一套规则。
感官模式、猫动作、回执绘制和小程序生命周期由客户端实现或配合实现。

## AI与常规逻辑
- AI：具体任务拆解、理解用户表达、情绪相关回应；不得将普通提问错误识别成替换任务。
- 粒度规则：耗时是辅助信号，用户主动反馈可立即调整；调整不能跳过必要动作或重复已完成动作。
- 模型返回必须校验非空步骤、文本类型及必要结构；失败有明确兜底。
- 计时、状态、权限、存储生命周期由程序逻辑负责；不依赖模型自行保证。

## 待定规则（不得擅自决定）
1. 真实AI与预设演示的范围：技术方案仍写前端预设，分工要求真实API。
2. 退出：直接清空与二次提供“再做一步”存在冲突。
3. 跨天：产品规定不提昨天任务，现代码提供跨天交接。
4. 历史与统计：设置历史入口与禁止历史列表、里程碑描述相互冲突。
5. 回执：产品要求客户端生成、不上传留言；现代码自动生成服务器手帐并提供留言存储。
6. 时间：轻承诺切后台是否继续、跨天时区、两个5分钟提醒冲突的处理尚需明确。

这些待定项不阻止核实和修复明确的代码错误，但不得据此擅自删除现有功能或承诺上线范围。
