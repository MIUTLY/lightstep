# LightStep 已确认需求与待定规则

更新日期：2026-11-07。

## 来源与决定

- 最新产品来源：用户提供的《粘贴的文本 (1).txt》，在此前 PDF 基础上补充了摩擦地图、本地手帐及跨天规则。
- 用户随后确认采用前后端分离：uni-app 小程序 + FastAPI + SQLite；回执及留言保存在客户端本地。
- 以 [architecture.md](architecture.md) 的技术和数据分工替代原策划“无后端、所有数据本地存储”的描述。
- 原始业务基线为 lightstep-backend(1).zip；现有网页调试页位于 backend/static/，不是微信小程序成品。

## 产品主线

聊天或输入目标 → 选择目标 → 现在/5分钟/10分钟后开始 → 五分钟轻承诺 → 单步执行及主动拆小 → 自主结束与可选回执。默认只显示当前一步，不催促、不吓人、不追究退出。

前台无操作五分钟召回、最多两次、支持勿扰，与轻承诺的五分钟独立计时；没有触摸不等于用户走神。

## 已确认技术边界

- 任务、步骤进度、偏好和摩擦地图在后端 SQLite 管理，客户端不能另行推进一份进度。
- 模型供应商密钥只放后端，实际模型效果须用真实配置验证；默认 mock 保持无密钥可调试。
- 任务步骤须可执行，调整不得跳过必要动作。主动反馈优先，耗时仅作辅助信号。
- 普通步骤提问不得创建或覆盖目标；便签操作前后任务状态一致。
- 回执图片与私人留言不上传、不分析、不自动保存；只有用户主动选择后存到本地或相册。
- 新实现停用服务端手帐写入与查询；旧 journal 数据不自动删除。
- 客户端负责计时、动效、勿扰和感官模式，实际小程序实现待前端源码接入。

## 尚未统一的产品规则

| 事项 | 原文冲突或缺失 | 本轮处理 |
| --- | --- | --- |
| 退出 | F4与路演直接清空，第8节仍二次挽留 | 保留现有直接退出行为，不新增挽留 |
| 跨天 | 轻提旧任务与首页不提昨天并存 | 保留现实现，待队长统一 |
| 历史 | 第9.3节允许隐藏历史，第11节禁止列表 | 不新增界面与统计，待队长决定 |
| 当天日志 | 无惩罚退出“无记录”与历史条目并存 | 未删除 day_log；保留期限待定 |
| 时间 | 切后台是否累计、跨天时区、两种五分钟同时触发 | 待定，不自行认定无操作为失败 |
| 执行页按钮 | 完成/结束与太重/完成两套说法 | 前端实施前统一布局 |
| 猫姿态 | 按完成步数变化与仅3种姿态并存 | 不扩展动画资产，待定 |

## 当前不包含

账号体系、多设备同步、后台系统推送、排行、连续天数和积分。既有代码仍有里程碑话术等差异，不能把本轮技术改造理解为全部产品规则已完成验收。

测试与剩余缺陷见 [handoff.md](handoff.md)；接口接入见 [api.md](api.md)。
