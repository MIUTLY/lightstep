# 行动辅助与进度，不做成果验收

2026-11-07。用户明确：LightStep把难事拆成能动手的小事，只记录用户自报的行动进度，不评价用户的正确率、完成质量或达标程度。

## 新生成任务规则

- 短、自然、直接的动作，帮助用户开始和推进；每个动作都要实际服务于原目标。
- 不为了系统管理而添加获取并确认、确认完整无遗漏、记录每题选项理由、汇报成果、自评、上传证据或另交最终答案等步骤。
- 例：数学难题可按需要拆成看看相关知识点、试写一种思路、动笔算一算。它只是说明行动风格，不能套成所有数学题或所有目标的固定模板。
- 如果记录、论证、检查、交付本身就是用户明确提出或工作必要的内容，保留；不能通过删除“理由”“检查”等词来篡改任务。例如写证明题、写实验报告、检查代码并不因此禁止。
- 范围澄清只问清影响拆分的对象与工作量，例如哪份作业、约定做几题；不索要题目全文、答案或选项来验题，不代做题。已有明确范围不强制重复问。
- 父子结构覆盖的是用户约定的行动范围，不是保证成果达标。仍不能用“打开作业”代替做完整份约定作业。

## 实现与接口

同一ACTION_SUPPORT_POLICY同时用于真实AI拆分、独立计划审核、范围澄清与范围审核，防止生成规则放宽了、审核却仍强制要求留证或验收。计划含与目标无关的额外验收负担时，既有relevant检查拒绝该计划，返回可重试失败，不静默删步骤或套模板。

完成接口参数不变。用户明确点击完成，只按当前节点未完成叶子更新进度；不提交答案、正确率、理由或成果，不请求AI评分。整项约定行动范围都由用户标为完成后才移出待办；中途结束继续保留剩余内容。回执只陈述用户标记的已做/剩余动作，不声称用户答案正确或目标客观达成。

展示沿用[public-ai-text.md](public-ai-text.md)：内部标签删除，必要的行动范围和剩余动作保留。改进源头AI措辞与多余动作，而不是盲目删掉所有括号内容或关键词；必要数量、题号、约束和父任务上下文不能因此丢失。

## 兼容与验收边界

已有任务森林和完成记录不自动重新生成或删除。新规则作用于之后的真实AI生成，已有截图里的旧步骤不会靠过滤擅自变更完成范围；旧任务如需换成新拆分，需用户主动重建，不清空旧进度冒充迁移成功。

测试验证真实适配器将行动政策传给生成/审核/澄清，隔离的审核拒绝会报错，以及完成流程不调用AI/不要求答案。它不证明真实模型每次都能生成理想计划；数学题、英语选择题、写作、家务等真实输出与微信显示仍需样本联调。前端不展示完整森林或内部原文，只展示当前一步并提供手动完成/轻重切换/中途结束。
