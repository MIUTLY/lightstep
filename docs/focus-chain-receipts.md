# 连续专注、返回对话与可填写回执

2026-11-08。本次用户明确确认：这里的大任务是备忘录中的独立项；做完一项自动执行下一项。本轮允许直接修改相关前后端，覆盖此前“整项完成后总是停留备忘录等待选择”的规则。

## 正常流程

1. 进入专注后，当前一步仍按森林节点执行；完成小步骤不切换备忘录项，不改变主动选择的档位。
2. 完成整项A后，先保存A的完成结果，再按当前所选日期清单的顺序选择首个未完成项B。复用已有森林及进度，未生成的B按原真实AI流程准备；新B默认第一中节点和表现第1步，不沿用A的位置。
3. B启动请求失败时，A不回滚、不重做。页面提供重试下一项，或允许用户结束本轮。B需要范围澄清时回对话页，不在专注页放无效询问卡片。
4. 所选日期清单最后一项完成后，回/pages/chat/chat，自动显示本轮回执。不会因为默认视图跳到其他日期就自动开始旧日任务。
5. 用户点“就到这儿吧”，只有end成功后返回对话页并弹回执。失败留在当前步骤、提示重试，不清空任务，不跳页，不保存空回执。中途退出仍按原规则保留真实叶子进度和独立表现步号。

连续多项属于一个本地专注轮次：各任务的后端receipt事实仍独立且准确，本地outbox记录到同一round；中间不弹窗。最终完成或明确退出后弹一张可填写回执，列入该轮事实；票根取最后一个实际专注任务的后端presentation，不累计跨任务步数、不随机挑图。下一项未启动时结束，本轮标为中断，不因上一项完成而误称整轮全部完成。

## 复用的后端接口

无需新增业务接口，也不修改模型适配器/任务森林算法。

```json
{"user_id":"demo","request_id":"完成重试复用的ID","action":"complete","session_id":"当前专注ID","step_id":"当前展示ID"}
```

POST /api/today/command成功后：focus仍存在则继续当前任务；focus=null且同日期仍有suggested_item_id，则发select启动该项；没有下一项则结束本轮。select失败不撤回已提交的complete。前端持久化complete/end/select请求ID，同一操作丢响应后重试复用ID，新的步骤或新一轮选择使用新ID。

```json
{"user_id":"demo","request_id":"结束重试复用的ID","action":"end","session_id":"当前专注ID"}
```

end成功应为focus=null，未完成项仍在items，receipt.outcome=interrupted。不能将退出实现为complete，不能在finally里无条件跳转。

## 前端状态与弹窗

- utils/focusFlow.js协调complete→select及本地轮次outbox，按用户ID隔离。先将回执事实持久保存，回对话后才ack后端事件。重开/重复响应不生成重复轮次或重复本地页。
- store/today.js保留原revision守卫，修复capture紧凑响应误清focus/items，网络失败不标记ack成功。
- pages/focusmode只协调执行、重试和退出；移除自动写空白手帐、旧文字召回及无条件返回备忘录。前台未操作换走神图规则保留。
- pages/chat恢复状态后显示FocusReceiptDialog；隐藏期间到达的响应不在隐藏页弹窗。

## 填写与保存

回执展示服务端选定的票根，下面有横线输入区，填写会实时合成到票根下半部分。预览和保存复用同一Canvas，使用实际日期覆盖原图固定日期；日期补丁取样按真实图片尺寸，不能按600×900画布坐标截原图。

点击“保存至手帐”才生成完整图片、持久保存图片并写本地日期索引。图片失败或索引失败都保留文字，不提示成功；索引失败清理未引用的新图片。相同轮次的保存重试用稳定页ID防重复，不同轮次同日追加，不覆盖旧页，不静默截断到500页。文字超出区域时提示缩短，不静默截18字或溢出保存。原有中性票根兼容也保留完整可容纳文字。

用户文字、合成图、草稿和轮次outbox仅在客户端保存，不上传、不调用AI评分。手帐新大底图仍未提供，未擅自绘制替代；本轮保存的是完整回执页，现有本地手帐日期轴/翻页可查看。

## 验证边界

自动化覆盖控制器、实际store、SFC script、Canvas调用参数和本地存储边界；不等于微信模板/WXSS编译或真机验收。需实测：A→B实时渲染、最后完成返回/弹窗、退出断网与重试、前后台恢复、弹窗层级/缩放、原生Canvas与输入框层级、填写文字预览/导出一致、日期覆盖、空间不足、同日多页和重新打开。
