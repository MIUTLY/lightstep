# 粒度切换保留动作顺序

日期：2026-11-07。分支：fix/preserve-step-sequence。基于上一轮fix/task-intent-and-validation的8bd7c4e；上一轮PR #4尚未合并，本轮PR以该分支为目标，只展示本轮差异。

## 复现与修改依据

B01：背单词的normal路线依次为打开单词本、过5个单词、标记不熟的词。第一步3秒完成后，原实现按列表长度把normal的1/3位置映射到coarse的1/2，直接显示标记步骤，学习动作被跳过。不同清单的相同比例并不表示完成了相同内容。

已确认需求要求步骤可执行，调整不得跳过必要动作，进度只由后端推进。

| 改了什么 | 依据与原因 |
| --- | --- |
| 用normal清单建立一条有序动作队列，移除比例映射 | 保留未完成动作，耗时只影响接下来展示多少，不推测已经做过什么 |
| 粗档合并相邻两个动作，细档拆当前动作并保留剩余数量 | 学习5个词可拆为1个与剩下4个，不能凭空变为“已完成5个”；拆分复合动作先保留顺序，避免重复后续通读动作 |
| 无法确认的拆分保持原文，不发起额外模型调用 | 否定、条件、页码、范围、分数等不能直接解释成工作量；此轮不引入不受控的改写与额外等待 |
| 任务响应增加step_id，前端与网页调试页优先用它判断换步 | 两个真实动作可能都叫“读一小段”，只比较文字会把上一动作的耗时累加到下一动作 |
| 小段结束改为“这一小段先到这” | 模板和模型生成的是启动小段，未证明覆盖“背50个词”等整个目标，不能误报全部完成 |
| 元数据写入已有levels_json，旧任务沿用当前清单与游标 | 不迁移SQLite表，不倒推历史完成情况；跨天存档原样带上队列及展示范围 |

已完成的前缀保留；完成只消费上次真正显示的动作，调整不会增加steps_done。steps_done仍按完成请求计数，并非原始动作数量。队列内部标识不展示给用户，也不作为请求幂等保护。
