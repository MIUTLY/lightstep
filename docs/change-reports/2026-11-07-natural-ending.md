# 自然收尾与疲惫反馈

日期：2026-11-07。分支fix/natural-task-ending，基于PR #5的1b0e4ecc。PR #4与#5尚未合并，本轮PR以fix/preserve-step-sequence为目标，只展示本轮差异。

## 依据与改动

B07：执行中说“我累了”只得到泛化的低落回复，缺少可操作的收尾选择。审查同时发现退出使用子串匹配，“不要结束”与“记一下六点结束”也会误删任务。已确认要求是用户自主收尾、不催促，普通提问不覆盖任务，有歧义时不误删任务。

| 修改 | 为什么 |
| --- | --- |
| 收尾必须匹配完整的常用分句，可带称呼、礼貌语与疲惫说明 | 出现“结束”二字不等于发出结束命令，未知上下文不直接执行删除 |
| 明确“今天先到这吧”“我想结束了”等直接走既有收尾 | 保持无额外挽留的退出流程，不新增确认步骤 |
| “我累了”“想休息一下”保留原任务并给出结束/拆小按钮 | 疲惫不等于已经选择结束；用户可以停，也可以调整，不能自动完成或清空任务 |
| 活跃任务不再使用宽泛的“今天不想”等休息子串清空任务 | “今天不想结束”表达的是继续，不能误判成休息日 |
| 空闲时的疲惫表达直接回应，不新建目标 | “我想休息一下”含“想”，但不应该被目标关键词创建为学习任务 |
| 常用收尾/疲惫不额外调用模型 | 这些状态选择由确定规则执行，避免等待模型或让模型回复决定数据库操作 |

buttons沿用前端已有的“今天到这吧”“太重了”标签及退出/拆小接口。疲惫反馈本身不写进度、完成记录、摩擦地图、便签或提醒；明确退出只清除当前任务，保留已有日志与其他数据，不生成手帐。

## 边界与后续

本轮是常用完整分句识别，未知补充、长句、多重修饰可能继续走普通对话。比如询问“我可以结束吗”保留任务并回应，用户仍可点收尾按钮；未增加暂停状态或修改跨天、历史、日志保留策略。

后续重点为5/10分钟预约、轻承诺到期、前端本地回执/手帐迁移、并发幂等和微信联调。初始任务拆解质量与所有自然语言的语义覆盖仍需要独立验收。
