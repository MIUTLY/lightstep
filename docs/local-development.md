# 小程序与本地后端联调

## 谁运行在哪里

小程序运行前端，FastAPI运行在电脑或云端，两者通过HTTP通信。GitHub保存源码，不会启动服务。开发时可以用自己的电脑做后端服务器；异地队员需要一个他们能访问的后端地址。

当前源码位于 frontend/，属于uni-app工程。用HBuilderX导入该目录，再选择“运行 → 运行到小程序模拟器 → 微信开发者工具”；需要先编译，不把Vue源码直接当作原生小程序工程。若不能自动打开，使用HBuilderX控制台显示的生成目录。

## 同一电脑的开发者工具

激活Python环境、在backend/安装requirements.txt后，运行python run.py。保持终端运行，浏览器访问 http://127.0.0.1:8000/api/health，应返回status=ok。前端默认DEFAULT_BASE_URL即为此地址的基地址。

本地HTTP调试时按开发者工具要求配置本地请求校验选项。小程序编译失败和HTTP请求失败是两类问题，先看HBuilderX/开发者工具第一条报错。

## 手机真机连接电脑

Windows PowerShell中，从backend/运行：

```powershell
$env:LIGHTSTEP_HOST = "0.0.0.0"
$env:LIGHTSTEP_PORT = "8000"
$env:LLM_PROVIDER = "openai"
python run.py
```

先访问/api/health验证网络，此接口不调用AI。命令行环境变量优先于.env；新任务必须在后端配置真实AI，未配置只明确报错，不使用mock生成。

用ipconfig查看电脑当前Wi-Fi连接的IPv4，例如192.168.1.8。该值仅示例，必须替换为自己的实际地址。

- 手机与电脑接同一局域网。
- 在手机浏览器打开 http://192.168.1.8:8000/api/health。
- 若打不开，排查IP、后端监听、网络隔离和防火墙对本地TCP8000端口的访问规则，无需关闭整个防火墙。
- 若浏览器能打开而小程序请求失败，查看开发者工具网络面板的具体错误，检查请求地址和本地调试校验设置。
- 前端frontend/config/index.js的DEFAULT_BASE_URL改为电脑地址；设置页的缓存地址覆盖默认配置，调试时检查该覆盖值。

127.0.0.1在手机上指手机自己，0.0.0.0是服务器监听地址，两者都不能作为手机访问电脑的目标地址。手机应请求电脑实际IP。电脑休眠、服务退出或离开该网络后，本地地址不再可用。

## 后续部署

多人异地联调或比赛展示需要稳定可达地址时，再部署后端并配置小程序对应的网络访问要求。本轮没有替用户购买服务器、配置公网或部署服务。

任务生成和内容复核是两次串行真实请求，共享后端默认30秒逻辑预算；当前前端请求超时35秒。本轮未改前端配置，网络阶段超时实际耗时及微信表现仍需联调。

参考：uni-app官方运行说明 https://uniapp.dcloud.net.cn/quickstart-hx 。
